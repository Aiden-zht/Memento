# 任务能力索引

Memento 管理能力按“Agent 要完成的活”组织，不按工具类型组织。工具只是实现手段，Agent 可自行选择脚本、搜索、patch、git 或子 Agent 来完成目标。

## 1. 读库

目标：找到当前任务该读的规则、知识和项目事实，不漏读、不误读。

触发：任何需要参考 Memento 的任务。

动作：判定任务模式 → 查任务类型索引 → 全文搜索/索引/provides 辅助定位 → 读候选 frontmatter → 使用前检查。

完成标准：加载文件的 `status/load/source/confidence/load_when` 与当前任务匹配；不把 inbox、素材、用户资料当规则源。

## 2. 写库

目标：把新内容写到正确目录，并保证可审计、可追溯、可被 Agent 使用。

触发：用户明确要求写入 KB、固化规范、更新 Memento、消化 inbox 或提交知识库变更。

动作：检查白名单/黑名单 → 选目录 → 补最小 frontmatter → 更新 index → 验证 → commit/push。

完成标准：lint 通过；相关 index 已更新；git clean；远端已 push。

## 3. 消化 inbox

目标：处理原始材料，不让 inbox 直接污染正式目录。

触发：用户说“消化 inbox”或向 inbox 投递资料。

动作：评审价值 → 必要时转换/拆分 → 默认进入用户资料或不入库 → 二次判断后晋升正式目录。

完成标准：每个输入都有处理结论；低置信度或临时材料不入正式目录；清理动作可追溯。

## 4. 健康检查

目标：确认 KB 结构可用、入口可用、没有断链或提交遗漏。

触发：用户说“健康扫描”“检查断链”“检查知识库”。

动作：检查 frontmatter、wiki-link、index、入口、git 状态、黑名单、deprecated 引用、目录深度。

完成标准：输出 PASS/FAIL；若 FAIL，列出 blocker 和修复建议。健康检查不等于内容存废审计。

## 5. 存废审计

目标：判断文件或目录是否还值得存在，避免 KB 变垃圾堆。

触发：用户说“哪些没用了”“清理垃圾”“存废审计”“这个文件要不要保留”。

动作：检查入链、index、任务索引、provides/requires、skill/cron/script/AGENTS 引用、source/confidence/load_when、重复/过时/低质量/单次任务痕迹。

完成标准：输出 `保留 / 合并 / 改成引用 / 标记 stale / deprecated / 删除 / 需要补证据`，并说明理由和依赖情况；删除前必须做断链和执行层依赖检查。

## 6. 迁移重构

目标：目录改名、文件移动、字段升级、规则重组后仍保持可用。

触发：顶层架构调整、目录迁移、frontmatter 迁移、规范拆分/合并。

动作：迁移文件 → 修 wiki-link/index/任务索引/入口 → 检查旧路径残留 → 验证 → commit/push。

完成标准：无断链；旧路径无生产引用；lint/audit/self-check 通过；执行层影响已判断。

## 7. 执行层对齐

目标：KB 规则变更后，skill、cron、script、AGENTS 不继续按旧规则运行。

触发：修改规则、产物规范、Agent 行为、项目契约、任务入口、目录结构或 frontmatter 语义。

动作：查受影响的执行资产 → 判断是否依赖该规则 → 修改或确认无影响 → 最小验证。

完成标准：相关执行资产通过 `requires_provides` / `kb_refresh_policy` / 运行时加载 / 验证命令感知新规则；无旧行为继续运行。

## 用户语言映射

| 用户说法 | 能力 |
|----------|------|
| “检查断链”“健康扫描” | 健康检查 |
| “哪些文件没用了”“清理垃圾” | 存废审计 |
| “消化 inbox” | 消化 inbox |
| “固化进 KB”“更新规范” | 写库 |
| “目录重构”“迁移字段” | 迁移重构 |
| “KB 改完会不会影响 skill/cron/script” | 执行层对齐 |
| “按知识库做这个任务” | 读库 |
