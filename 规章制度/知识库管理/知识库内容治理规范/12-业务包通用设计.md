# 业务包通用设计

## 定位

业务包是各项目独立维护的规范集合，不在 Memento 知识库中。Memento 只定义结构标准和创建流程，不存放任何具体业务内容。

```
Memento 知识库         → 治理规范 + 通用知识（品牌无关）
业务项目 specs/        → 业务规则 + 技术参考（品牌相关）
Agent                  → 读 Memento 知道"怎么做业务包" → 读业务包知道"怎么做业务"
```

## 标准结构

```
{项目根目录}/specs/
├── index.md          # 业务包声明（必须）
├── rules/            # 业务规则（流程、质量、合规）
└── references/       # 技术参考（API 手册、模板、风格参考）
```

## index.md 字段定义

| 字段 | 必需 | 类型 | 说明 |
|------|------|------|------|
| `business` | 是 | string | 业务名称（中文，不含平台/产品名） |
| `domain` | 是 | array | 业务域：`writing` / `coding` / `ops` / `data` |
| `description` | 是 | string | 一句话描述 |
| `depends_on` | 是 | array | 依赖的 Memento `provides` 标签 |
| `provides` | 是 | array | 本业务包提供的标签 |
| `kb_refresh_policy` | 是 | string | 固定为 `runtime` |
| `created` | 是 | string | 创建日期 |

## 业务域与默认依赖

| domain | 适用场景 | 默认 `depends_on` |
|--------|---------|-------------------|
| `writing` | 文章写作、内容发布 | `Agent行为约束`, `写作通用规范索引` |
| `coding` | 代码开发、代码审查 | `Agent行为约束` |
| `ops` | 运维、部署、监控 | `Cron流水线运维`, `Agent行为约束` |
| `data` | 数据管道、数据分析 | `Agent行为约束` |

Agent 根据用户描述推断 `domain` 并自动匹配默认依赖。用户可手动增减 `depends_on` 标签。

## Agent 创建流程

### 触发条件

- 用户说"新建业务""创建业务包"或类似指令
- 用户描述新需求时，Agent 检查当前项目是否有 `specs/`，若无则主动询问是否创建

### 创建步骤

1. 读取 Memento `_templates/business-package/index.md` 获取骨架
2. 根据用户描述推断 `domain`，匹配默认 `depends_on`
3. 在项目根目录创建 `specs/` 及子目录
4. 填充 `index.md` 全部字段
5. 与用户对话逐步明确 `rules/` 内容
6. 执行自检验收（见下）
7. 完成后告知用户业务包路径和已声明的依赖标签

## Agent 发现机制

Agent 执行任何任务前，按以下顺序检查：

1. 检查当前工作目录下是否存在 `specs/index.md`
2. 若存在 → 读取 `depends_on` → git pull 加载 Memento 对应规范 → 加载 `rules/` 和 `references/`
3. 若不存在 → 按常规流程执行（仅依赖 Memento 通用规范）

业务包的 `provides` 标签仅在业务包内部使用，不入 Memento 标签索引。

## 自检验收

Agent 创建业务包后，必须自检，但无需逐项输出清单到对话中——内化为工作习惯：

| # | 检查项 | 失败处理 |
|---|--------|---------|
| 1 | `specs/index.md` 存在且 YAML 可解析 | 重建 |
| 2 | `depends_on` 中每个标签在 Memento 中可查到（全文搜索验证） | 移除无效标签或先补建 Memento 规范 |
| 3 | `business` 字段不含平台名或产品名 | 修正 |
| 4 | `domain` 字段值在允许集合内 | 修正 |
| 5 | `rules/` 和 `references/` 目录存在 | 创建 |

## 禁止行为

- 禁止将业务规则写入 Memento 知识库
- 禁止在 `business` 字段中使用平台或产品名
- 禁止在 `depends_on` 中声明不存在的 Memento 标签（Agent 必须验证后再声明）
- 禁止跨业务包引用对方的内部文件（应通过 Memento 通用规范共享规则）

## 与 Memento 的关系

| Memento 职责 | 业务包职责 |
|-------------|-----------|
| 定义业务包结构标准 | 按标准创建和维护 |
| 提供通用规范（写作方法论等） | 声明依赖，运行时加载 |
| 不存储任何具体业务规则 | 存储本业务的所有规则 |
