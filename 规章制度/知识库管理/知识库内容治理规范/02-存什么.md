# 存什么（白名单）

以下 6 类内容可以存入知识库：

> **人怎么用**：不用管分类。把文章扔进 `inbox/`，对 Agent 说"消化 inbox"，Agent 会先评审是否值得长期入库，再按需归类。
>
> **注意**：日常操作备案（安装软件、修改配置等）不属于知识库内容，只存于项目根目录 `{{WORKSPACE}}/操作备案.md`，不入库。

## 2.1 规范文档

Agent 必须遵守的规则和标准。

| 示例 | 特征 |
|------|------|
| 发布流程与质量规范 | 定义 Agent 必须执行的业务流程 |
| 多Agent知识库协作规范.md | 定义 git 协作规则 |
| [[规章制度/知识库管理/知识库内容治理规范/index]] | 本规范索引 |
| 平台合规细则 | 平台特有的合规红线 |

**判断标准**：这个文件是否定义了 Agent「必须做什么」或「不能做什么」？

## 2.2 技术参考

Agent 可查阅但不强制执行的资料。

| 示例 | 特征 |
|------|------|
| 平台API开发手册.md | API 调用参考 |
| 内容模板.md | 排版样式参考 |
| 外部政策、法规、制度原文 | 有长期参考价值，但不约束 Agent 行为 |
| `知识/<主题>/index.md` | 用户自建长期参考知识 |

**判断标准**：这个文件是否提供了 Agent「可以参考」的信息？

## 2.3 项目文档

项目的说明、设计、架构文档。

| 示例 | 特征 |
|------|------|
| 项目 `specs/index.md` | 项目业务包入口 |
| 知识库内容治理规范.md | 治理规则文档 |
| KPI系统实现方案.md | 系统设计文档 |

**判断标准**：这个文件是否解释了「这个项目/系统是什么、怎么用」？

## 2.4 决策记录

重要技术决策、架构选择、方案对比的记录。

| 示例 | 特征 |
|------|------|
| 面试经验.md | 经验记录 |

**判断标准**：这个文件是否记录了「为什么选择这个方案/技术路线」？或「发生了什么、为什么这样做」？

## 2.5 示例库

经过人工审核的 few-shot 学习样本。

**判断标准**：这个文件是否被人工标记为「高质量/低质量样本」？

## 2.6 治理标准

定义知识库自身管理规则的文件。

**判断标准**：这个文件是否定义了「如何管理这个知识库」？
