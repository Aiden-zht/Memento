# 文件生命周期

## 6.1 创建

| 触发条件 | 操作 |
|----------|------|
| 新增规则/标准 | 创建文件，加入目录 index |
| 新增产物规范 | 放入 `产物规范/` 对应目录，写明验收标准 |
| 新增专业知识 | 放入 `专业知识/`，必须有 source / confidence |
| 新增素材 | 放入 `素材库/`，必须说明复用场景 |
| 新增项目长期事实 | 放入 `项目知识/<项目>/`，不得混入运行状态 |
| 新增来源材料 | 默认进入 `用户资料/` 或保留在 `inbox/` 待消化 |

创建前检查：是否属于 KB、是否已有类似文件、目录 index 是否合格、frontmatter 是否满足 [[规章制度/知识库管理/知识库内容治理规范/05-文件规范]]。

## 6.2 文件状态

| 状态 | 含义 | 使用规则 |
|------|------|----------|
| `active` | 当前有效 | 可作为对应权威层级下的依据 |
| `draft` | 草稿 | 仅参考，不作为正式依据 |
| `stale` | 疑似过时 | 使用前必须复核 source/confidence/项目现状 |
| `deprecated` | 已废弃 | 应指向替代文件，不长期保留 |
| `archived` | 历史记录 | 不参与生产任务加载 |

非 `active` 文件不得被生产任务直接引用为依据。

## 6.3 更新

| 触发条件 | 操作 |
|----------|------|
| 规则/验收标准变化 | 更新正文，核心文件同步 `version/changelog` |
| 来源或事实变化 | 更新 `source/confidence/last_reviewed` |
| 内容过时 | 标记 `stale`、更新或删除 |
| 文件被执行层依赖 | 检查 skill/cron/script/AGENTS.md 是否需同步 |

实质性规则变化后必须 lint、commit、push。

## 6.4 目录审计

所有正式知识目录必须有 `index.md`。目录 index 必须包含：目录定位、收录范围、禁止内容、权威边界、加载条件、维护方式、审计规则、清理规则。

无合格 index 的目录只能作为临时/迁移目录，不视为正式知识源。index 只细化本目录，不复制全局规则。

## 6.5 stale / deprecated / delete

| 情况 | 动作 |
|------|------|
| 来源失效、置信度不足、项目事实疑似变化 | 标记 `stale`，使用前复核 |
| 被新文件替代但短期需要转向 | 标记 `deprecated`，正文指向替代文件 |
| 无来源、重复、低质量、只服务单次任务、长期无引用、误导 Agent | 删除，历史由 git history 保留 |
| 包含密钥、运行状态、缓存、日志、生成产物 | 立即删除并检查 git 历史风险 |

不要建立长期 archive 内容库；归档目录会增加 Agent 检索噪声。

## 6.6 删除前依赖检查

删除或废弃前必须检查：

1. wiki-link 入链；
2. 目录 index 和上级 index；
3. `provides/requires` 标签依赖；
4. skill / cron / script / AGENTS.md / 任务类型索引是否引用；
5. 项目知识是否仍是项目契约或测试策略的一部分。

普通素材和用户资料如无执行依赖，清理成本应低；规则、产物规范、项目契约必须先确认替代来源。

## 6.7 文件变更伴随动作矩阵

| 变更类型 | 必须检查/修改 | 验证方式 |
|----------|---------------|----------|
| 新增普通文件 | frontmatter、所在目录 index | lint；确认 index 有入链 |
| 新增目录 | 目录 index、上级 index | audit；确认不依赖目录 fallback |
| 修改规范/流程/检查项 | `version/changelog`、任务入口、执行层依赖；若属于重大治理裁定，追加治理复盘 | lint；按 7.6 判断实现影响 |
| 修改 frontmatter | YAML 可解析；`type/status/load/source` 语义准确 | lint；必要时搜索验证 |
| 重命名/移动 | 全库 wiki-link、原目录 index、新目录 index、上级 index | 搜索旧路径；audit |
| 删除文件 | 入链、index、执行层依赖 | 搜索文件名/路径；lint |
| 标记 deprecated | 正文写明替代文件；上游引用改到替代文件 | 搜索入链 |

## 6.8 回滚

Agent 改错内容、commit 并 push 后，优先向前修复；若错误涉及多个文件、已被其他 Agent 读取执行、或形成有害快照，则用 `git revert` 回滚。

```bash
git log --oneline -10
git revert <commit_hash>
bash scripts/lint-knowledge-base.sh
git push origin master
```

回滚后检查入链、索引、provides/requires、下游执行层是否仍指向正确规则。
