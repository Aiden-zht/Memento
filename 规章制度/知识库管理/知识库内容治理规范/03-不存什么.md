# 不存什么（黑名单）

以下内容**禁止**存入知识库：

## 3.1 中间状态文件

```
❌ state.json — 流水线中间状态
❌ *.state.json — 所有状态文件
```

> **注意**：`.last_seen_commit` 是 Agent 本地 git 状态标记文件，`pull-and-check.sh` 依赖它记录上次同步位置。此文件不入 git（`.gitignore`），存放在工作区本地，不属于"中间状态文件"范畴——它类似 `.git/HEAD`，是 git 工作流的本地锚点。

**原因**：这些是运行时数据，不是知识。每次运行都会覆盖。

**正确做法**：存到工作区 `{{WORKSPACE}}/output/`，不入 git。

## 3.2 生成产物

```
❌ output/ — 生成的文章
❌ terraria_article.html — 生成的 HTML
❌ digest_*.md — 生成的摘要
```

**原因**：这些是 Agent 的输出，不是知识。可以重新生成。

**正确做法**：存到工作区，用完即弃。

## 3.3 临时分析

```
❌ 临时调研结果 — 未经整理的原始数据
❌ 调试日志 — 排查过程记录
❌ 会话历史 — 对话记录
```

**原因**：这些是一次性信息，没有持久价值。

**正确做法**：会话内消化，不入 git。

## 3.4 二进制文件

```
❌ 图片文件（.jpg, .png）— 除必要引用外
❌ 音视频文件
❌ 压缩包
```

**原因**：git 不适合管理二进制文件，会膨胀仓库体积。

**正确做法**：图片上传到 CDN 或存储服务，文档中引用 URL。

## 3.5 过期内容

```
❌ 已过时的配置信息（如旧的 API 地址）
❌ 已废弃的功能说明
❌ 已被替代的旧版本文档
```

**原因**：过期信息会误导 Agent。

**正确做法**：无工作流依赖时直接删除，历史由 git history 保留；只有短期内仍需明确提示“不要使用”的内容，才保留 `status: deprecated`。

如临时保留 `archive/` 目录：

- archive 内容默认不参与日常任务加载。
- archive 内容不作为 Obsidian 主图谱节点维护。
- archive 内断链不触发主库修复，除非该文件被重新启用。
- 需要恢复使用时，必须移出 archive，更新 frontmatter、链接、version/changelog，并通过 lint。
