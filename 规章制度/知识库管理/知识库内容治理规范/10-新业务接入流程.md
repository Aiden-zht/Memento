# 新业务接入流程

> 新增业务领域（抖音、小红书等）时的操作 checklist。
>
> 所有 Agent 创建新业务目录前，必须先阅读此文档。

---

## 接入流程

### Step 1：创建目录结构

```
业务/{业务名称}/
├── 创作规范/           # 创作相关的规范和参考
│   ├── 发布流程与质量规范.md   # 发布流水线定义
│   ├── 风格库.md              # 内容风格指南
│   ├── 合规与安全.md          # 平台合规红线
│   └── few-shot-examples/     # 人工审核示例
└── 项目文档/           # 项目说明和设计
    └── index.md              # 项目概述
```

### Step 2：继承基础设施规则

以下内容来自 `规章制度/`，新业务自动适用，**无需重新创建**：

| 文档 | 说明 |
|------|------|
| [[规章制度/Agent协作/多Agent知识库协作规范]] | git 协作、commit 格式、冲突处理 |
| [[规章制度/知识库管理/知识库内容治理规范/index]] | 内容边界、文件规范、生命周期 |
| [[业务/写作/通用/07-KPI评分通用框架]] | 质量评分规范 |

### Step 3：创建必需文档

| 优先级 | 文件 | 说明 |
|--------|------|------|
| P0 | `创作规范/发布流程与质量规范.md` | 定义该平台的发布流水线、质量检查规则 |
| P0 | `项目文档/index.md` | 项目概述、架构、环境变量 |
| P1 | `创作规范/合规与安全.md` | 平台禁止内容、封号风险、版权规则 |
| P1 | `创作规范/few-shot-examples/index.md` | 学习样本库说明 |
| P2 | `创作规范/风格库.md` | 内容风格、标题公式、排版规范 |

### Step 4：更新 index 索引

在根目录 `index.md` 的「第三层：业务」下追加新业务入口。

### Step 5：配置 Agent 加载

对应 Agent 的启动 prompt 中声明加载路径：
```
【业务层】业务/{业务名称}/  ← 仅该业务 Agent 需加载
```

---

## 业务目录规范

| 规则 | 说明 |
|------|------|
| 目录命名 | 中文，如 `公众号`、`抖音`、`小红书` |
| 层级限制 | `业务/{领域}/` 下不超过 5 层 |
| 文件行数 | 同治理规范，≤500 行 |
| 交叉引用 | 优先用 ``业务/{领域}/...`` 完整路径 |
