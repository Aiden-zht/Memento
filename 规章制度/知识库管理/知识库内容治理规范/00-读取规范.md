# 读取前必须 git pull

> **任何模型在读取知识库之前，必须先执行 `git pull` 获取最新版本。**

## 为什么

本知识库由多个 Agent 通过 git 协作维护。如果你读取的是旧版本，可能会：
- 读到已被删除或修改的文件路径
- 错过其他 Agent 提交的重要更新
- 基于过期信息做出错误决策

## 标准做法

```bash
cd /path/to/memento
git pull origin main
```

如果你使用的 Agent 不支持在知识库目录下执行 shell，可在 session 初始化 prompt 中注入：

```
[系统提示] 在读取知识库前，请先确认已获取最新版本。
```

## 脚本说明

| 脚本 | 用途 | 何时运行 | 违反后果 |
|------|------|---------|---------|
| `bash scripts/lint-knowledge-base.sh` | 检查全部 `.md` 文件是否符合治理规范 | 每次**改动后**、**commit 前** | E01-E05 错误阻止 commit |
| `bash scripts/pull-and-check.sh` | `git pull` + 列出本机未见过的新 commit（记录到 `.last_seen_commit`） | 每次 session 初始化时 | 不知其他 Agent 改了啥，可能用旧知识 |
| `scripts/provides-search.py` | 按 provides 标签辅助查找 KB 文件，支持 `--synopsis` 和 `--files` | 已知标签或 cron prompt 固定依赖时 | 不应作为唯一搜索入口 |
| `scripts/install-hooks.sh` | 将 `scripts/pre-commit` 安装为 git hook | 新 clone 后一次性执行 | commit 前不自动跑 lint |
| `scripts/pre-commit` | 被 git hook 调用，commit 前自动跑 lint | git commit 触发 | — |

## lint 检查范围

当前 lint 只负责硬性结构质量：frontmatter、文件名、行数、wiki-link、version/changelog 格式。`versions`、provides 术语表一致性和任务索引标签一致性不再作为阻断项；Agent 应通过全文搜索 + synopsis 筛选保证召回。

## Agent 原生能力优先

读取 KB 时优先使用 Agent 已有能力：全文搜索、语义理解、上下文推理、工具验证和 git history。KB 只提供任务入口、硬规则、业务流程、验证要求和持久约束。不要为了替代搜索或语义理解而新增受控词表、覆盖率指标、复杂语义 lint 或全库版本数据库。

## Agent 工作流

1. **Session 初始化**：`git pull origin main` 或 `bash scripts/pull-and-check.sh`
2. **判断任务类型**：先读 `规章制度/知识库管理/任务类型索引.md`
3. **发现候选文件**：优先用全文搜索（`search_files` / `rg`）找关键词、任务名、规则名
4. **筛选文件**：读候选文件 frontmatter，优先看 `synopsis`、`load`、`status`，再看 `provides`
5. **执行任务**：读取相关规范正文，不得跳过任务索引中标记的强制规则
6. **改动 KB 后**：运行 `bash scripts/lint-knowledge-base.sh`，无 E 类错误后才能 commit + push

## 运行时规范对齐原则

- 对话 Agent：不维护长期版本表；每次 `git pull` 后直接读取最新 KB。
- Cron Agent / 自建 skill / 本地脚本：如果依赖 KB 规范，必须声明 `requires_provides`，执行前读取最新 KB 并判断变更是否影响实现。
- `version` + `changelog` 是通用轻量变更提示；`versions/spec_versions` 只在硬编码脚本、长期 cron 状态追踪、无法运行时加载 KB 的实现中按需使用。

完整规则见 [[规章制度/知识库管理/知识库内容治理规范/07-Agent行为约束#7.6-本地实现运行时规范对齐契约]]。

## 搜索参考

| 场景 | 推荐方式 |
|------|----------|
| 不知道文件在哪 | `search_files(pattern="关键词", target="content")` 或 `rg "关键词" --include="*.md" -l` |
| 命中多个候选 | 读前 20 行，按 `synopsis` + `load` 判断 |
| 已知 provides 标签 | `python3 scripts/provides-search.py --synopsis 标签1 标签2` |
| cron 固定依赖 | 在 prompt 的 Step 0 固定写明依赖标签和加载命令 |
