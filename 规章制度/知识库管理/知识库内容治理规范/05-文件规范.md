# 文件规范

## Frontmatter 原则

每个 `.md` 文件必须有 YAML frontmatter。字段采用“全局最小 + 条件必填”：只保留 Agent 判断能不能用、何时用、可信不可信所需信息，禁止把 KB 做成数据库。

## 全局必填字段

```yaml
---
title: "文件标题"
type: rule | content_spec | domain_knowledge | material | project_knowledge | user_source | inbox | index | template | script
status: active | draft | stale | deprecated | archived
load: default | conditional | manual | never
---
```

| 字段 | 用途 |
|------|------|
| `title` | 人和 Agent 可读标题 |
| `type` | 文件类型，辅助判断权威层级 |
| `status` | 生命周期状态；非 active 不得直接作为生产依据 |
| `load` | 加载策略；决定是否默认、按条件、手动或永不加载 |

兼容说明：旧文件中的 `date`、`tags`、`category` 可保留；新规则不再把它们作为治理语义的核心字段。旧 `load: on-demand/index/workflow/template/archive` 在迁移期可读，但新文件应使用新枚举。

## 条件必填字段

| 字段 | 何时必填 | 用途 |
|------|----------|------|
| `source` | 专业知识、素材库、项目知识、用户资料；或任何事实/判断类内容 | 来源可追溯 |
| `confidence` | 涉及事实、判断、经验结论时 | `high` / `medium` / `low`，供引用前判断 |
| `last_reviewed` | 长期知识、项目事实、素材库内容 | 最近一次审计日期 |
| `load_when` | `load: conditional` 或 `manual` 时 | 说明何种任务场景加载 |
| `synopsis` | 需要被搜索筛选、任务入口或目录 index 引用时 | 一句话说明“管什么、何时读” |
| `provides` / `requires` | 被 skill、cron、script、AGENTS.md 或任务入口依赖时 | 建立运行时加载与执行层闭环 |
| `version` / `changelog` | 核心规范、产物规范、项目契约、被执行层依赖的文件 | 判断规则变更是否影响实现 |

## 不建议默认使用

不做全局必填：`owner`、`maintainer`、`review_policy`、`stale_after`、`versions`。

原因：默认维护主体是 Agent；这些字段容易制造维护幻觉。只有长期 cron、生产 skill、脚本硬依赖的核心规范，才按需使用 `versions` 或更细状态。

## 加载枚举

| load | 含义 |
|------|------|
| `default` | 入口/少量冷启动必读内容 |
| `conditional` | 根据任务类型、项目、产物类型按需加载 |
| `manual` | 仅用户明确要求或 Agent 评审需要时加载 |
| `never` | 模板、历史、原始材料等不得作为生产依据 |

## 状态枚举

| status | 含义 |
|--------|------|
| `active` | 当前有效 |
| `draft` | 草稿，仅参考，不可作为正式依据 |
| `stale` | 疑似过时，使用前必须复核 |
| `deprecated` | 已废弃，应指向替代文件，不长期保留 |
| `archived` | 历史记录，不参与生产任务加载 |

## 命名与大小

| 规则 | 说明 |
|------|------|
| 索引文件 | 每个含 `.md` 内容的正式目录必须有 `index.md` |
| 文件名 | 中文清晰表达内容，不含空格和特殊字符 |
| 单文件行数 | ≤ 600 行；建议 ≤ 200 行，过大则拆分 |
| 目录层级 | ≤ 5 层 |

## 交叉引用

使用纯 wiki-link 链接相关文档：双中括号内必须是完整路径，不使用竖线别名；目录索引明确写到 `/index`。

```text
- [[规章制度/知识库管理/知识库内容治理规范/index]]
```
