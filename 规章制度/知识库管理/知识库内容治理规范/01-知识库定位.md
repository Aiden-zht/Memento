# 知识库定位

## 这是什么

```
agent_mem = 知识库（git 跟踪）
  +-- 规范文档（Agent 必须遵守的规则）
  +-- 技术参考（Agent 可查阅的资料）
  +-- 项目文档（项目说明和设计）
  +-- 决策记录（架构选择、技术对比）
  +-- 示例库（few-shot 学习样本）
  +-- 治理标准（本文件）
```

## 这不是什么

**文件层面：**

```
agent_mem ≠ 工作区
agent_mem ≠ 缓存
agent_mem ≠ 日志
agent_mem ≠ 临时存储
```

**职责层面——KB 不管这些：**

KB 是规范文档仓库，不是 Agent 运行时基础设施。以下全部是 **Agent 执行层**的职责，KB 不负责：

| KB 不管 | 谁管 |
|---------|------|
| Skill 的创建、备份、迁移 | Agent 自己（`requires_provides` + `kb_refresh_policy: runtime`） |
| Cron job 的配置、调度、监控 | Agent 运行时调度器 |
| "改了 X 规范，影响哪些 skill" 的反向查询 | Agent 自己（正向：`provides-search`；反向：Agent 全文搜索） |
| 通知、告警、异常上报 | Agent 运行时平台 |
| Agent 运行时状态（KPI 分数、中间产物） | Agent 本地 `~/.hermes/skills/<name>/state/` |

> **一句话：KB 是宪法，不是政府。** 它定义规则，不执行规则。任何"KB 应该自动做 X"的需求，先问：这是规范定义还是执行动作？后者归 Agent。

## 边界原则

| agent_mem（本仓库） | `{{WORKSPACE}}`（工作区） |
|---------------------|----------------------------------------|
| 持久化的知识 | 运行时产生的数据 |
| 经过审核的内容 | 原始输出 |
| 所有 Agent 共享的长期知识（可包含特定项目长期知识） | 运行时代码、产物、日志、缓存、临时状态 |
| 版本化、可追溯 | 可随时覆盖 |

> 特定项目内容不是自动排除出 Memento；只有需要多 Agent 长期共享、可审计、可版本化的项目事实、契约和项目特有规则才进入 `项目知识/`。当前进度、运行结果、草稿 ID、日志、缓存仍属于工作区或 Agent 运行时。
