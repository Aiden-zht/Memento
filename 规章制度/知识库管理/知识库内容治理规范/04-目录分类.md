# 目录分配规则

Memento 按 Agent 使用方式分层，不按行业分层。用户不手工维护目录；Agent 在 inbox 消化、任务复盘或用户明确说“以后参考”时维护。

## 顶层结构

```text
memento/
+-- 规章制度/      # 最高权威：KB 和 Agent 自身怎么运行
+-- 产物规范/      # 高权威：各类产物怎么做、怎么验收
+-- 专业知识/      # 判断参考：领域/技术/行业知识，非规则源
+-- 素材库/        # 低权重参考：案例、故事、金句、片段、失败案例
+-- 项目知识/      # 项目内事实：repo/系统长期事实与契约
+-- 用户资料/      # 来源层：用户投喂后消化的资料，不自动成规则
+-- inbox/         # 原始入口：未消化材料，不是正式知识
+-- scripts/       # 维护工具，非知识权威源
+-- _templates/    # 结构模板，非知识权威源
```

`scripts/` 和 `_templates/` 只能实现、检查或承载结构；规则必须写在 `规章制度/`，不能只藏在脚本或模板里。

## 分类判断

| 内容 | 归入 | 权威级别 | 默认加载 |
|------|------|----------|----------|
| KB/Agent 行为规则、目录治理、生命周期、审计规则 | `规章制度/` | 最高 | 按任务加载 |
| 文章、代码、报告、视频、PR、文档等产物的制作与验收 | `产物规范/` | 高 | 生成/验收对应产物时加载 |
| 领域知识、技术知识、行业判断、理论框架 | `专业知识/` | 中，判断参考 | 不默认加载 |
| 案例、故事、金句、标题、代码片段、配置样例、失败案例 | `素材库/` | 低，表达/示例参考 | 不默认加载 |
| 具体 repo/系统的长期事实、架构、接口契约、测试策略、项目特有规则 | `项目知识/` | 项目内中高 | 相关项目任务加载 |
| 用户投喂并消化后的来源材料 | `用户资料/` | 来源层 | 不默认加载 |
| 原始未消化材料 | `inbox/` | 无正式权威 | 仅消化任务加载 |

## 产物规范 / 项目知识判定语

- 产物规范管“做出来是否合格”：文章、代码、报告、视频、PR、文档等产物的结构、流程、质量标准和验收规则。
- 项目知识管“该项目长期如何理解、调用、验证和操作”：具体项目的长期事实、架构、接口契约、测试策略和项目特有规则。
- 通用规则上提到 `产物规范/` 或 `规章制度/`；只绑定某个项目、离开该项目就失效的规则，才留在 `项目知识/<项目>/`。
- 运行结果、当前进度、日志、草稿 ID、缓存、一次性 debug 记录不进 KB。

## 禁止混入

- `专业知识/` 不放临时结论、运行状态、prompt 片段。
- `素材库/` 不作为规则源或事实权威源。
- `项目知识/` 不放日志、缓存、当前进度、运行结果、密钥、一次性 debug 记录。
- `用户资料/` 可引用、可追溯，但不自动升格为规则。
- `inbox/` 不能被生产任务直接当正式知识使用。

## 目录审计准入

所有正式知识目录必须有 `index.md`。没有合格 `index.md` 的目录，不视为正式知识源。

目录 `index.md` 必须说明：目录定位、收录范围、禁止内容、权威边界、加载条件、维护方式、审计规则、清理规则。index 只细化本目录，不重复全局规则。
