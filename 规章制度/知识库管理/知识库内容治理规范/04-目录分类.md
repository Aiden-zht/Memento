# 目录分配规则

新文件创建时，按以下规则选择目录：

```
memento/
+-- inbox/                  # (入口) 人扔文章的地方，Agent 自动消化归类
+-- 规章制度/              # (L1) Agent 必须遵守的治理规范 — 正文按任务加载
|   +-- Agent协作/         # Agent 间协作规则
|   +-- 知识库管理/        # 知识库自身治理（本文件）
|   +-- Cron流水线运维规范/ # cron 任务运维
+-- 知识/                  # (L2) 跨领域独立知识（按需加载）
|   +-- GPU分享/
|   +-- 面试经验/
|   +-- CAD制图/
|   +-- 团队沟通/
|   +-- Python打包部署/
|   +-- Nginx/
|   +-- 写作方法论/        # 写作通用规范（原 业务/写作/通用）
+-- _templates/            # 通用模板（Agent 创建业务包等时以此为骨架）
|   +-- business-package/  # 业务包骨架模板
```

> **业务内容不入 KB**：各项目的业务规则（平台 API、风格库、发布流程等）由项目 `specs/` 独立维护，见 [[规章制度/知识库管理/知识库内容治理规范/12-业务包通用设计]]。
>
> **规章制度边界**：`规章制度/` 的“规章”指 Memento/Agent 必须遵守的治理规范，不是外部文件标题里的“条例、制度、规定、意见”。外部政策、法规、组织制度原文如有长期参考价值，默认归入 `知识/`；如无长期复用价值，不入库。

## 分类判断流程

```
新文件要存入知识库？
    |
    v
是规范/规则/标准（Agent 必须遵守的治理规范）？
    +-- YES -> 规章制度/
    +-- NO
            |
            v
    是跨领域独立知识（GPU、面试、写作方法论等）？
        +-- YES -> 知识/
        +-- NO
                |
                v
        是通用模板（Agent 创建新业务/项目时以此为骨架）？
            +-- YES -> _templates/
            +-- NO -> 不存入知识库（可能属于项目 specs/ 业务包）
```
