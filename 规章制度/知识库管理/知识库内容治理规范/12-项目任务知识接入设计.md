# 项目任务知识接入设计

## 定位

新项目、长期任务或新的产物类型接入 Memento 时，不建立独立的外置规则源。默认规则权威源是 Memento 仓库内的正式目录，尤其是 `项目知识/<项目>/`；外部项目目录只存代码、运行状态和产物，除非用户明确指定外部项目知识源。Agent 按内容用途写入 Memento 的正式目录：

| 内容 | 归入 |
|------|------|
| 产物怎么做、怎么验收 | `产物规范/` |
| 具体项目/repo/系统的长期事实、接口契约、测试策略 | `项目知识/<项目>/` |
| 领域判断、技术知识、行业知识 | `专业知识/` |
| 案例、标题、代码片段、失败案例 | `素材库/` |
| 用户投喂的来源材料 | `用户资料/` |
| 原始未消化材料 | `inbox/` |

## 创建触发

- 用户明确说“新项目”“长期维护这个项目”“以后这类任务按这个标准做”。
- Agent 发现某类任务会反复出现，且需要多 Agent 长期共享规则或项目事实。
- 用户明确要求固化为 Memento 知识。

仅一次性产物、临时方案、当前会话草稿，不触发接入。

## 接入流程

1. 先判定任务模式：普通产出 / KB 使用 / KB 维护。
2. 判断内容类型：产物标准、项目事实、专业知识、素材、用户来源或原始材料。
3. 检查目标目录 `index.md` 是否允许收录；没有合格 index 时先建 index。
4. 新建或更新文件，按 [[规章制度/知识库管理/知识库内容治理规范/05-文件规范]] 补 frontmatter。
5. 更新目标目录、上级目录和根索引。
6. 若改动影响 skill、cron、script、AGENTS 或任务入口，按 [[规章制度/知识库管理/知识库内容治理规范/07-Agent行为约束]] 做执行层对齐。
7. lint、audit、self-check 后 commit + push。

## 项目知识最小结构

默认路径位于 Memento 仓库内：`/path/to/memento/项目知识/<项目名>/`。公开版或其他部署可替换仓库根路径，但不得把外部代码项目目录默认为规则权威源。

```text
项目知识/<项目名>/
├── index.md        # 项目定位、收录范围、加载条件、审计规则
├── 架构.md         # 长期架构与模块职责（可选）
├── 接口契约.md     # 输入输出/API/数据契约（可选）
└── 测试策略.md     # 长期测试/验收策略（可选）
```

不默认创建空文件；只有有真实内容时才创建。

## 禁止行为

- 禁止把运行状态、日志、缓存、当前进度、密钥写入项目知识。
- 禁止把素材库案例当作规则或事实权威。
- 禁止为了“以后可能有用”创建空壳目录。
- 禁止建立与 Memento 正式目录并行的长期规则源。
- 禁止把外部项目代码目录中的说明文件默认当作项目任务知识权威；若用户显式指定外部项目知识源，必须在 Memento `项目知识/<项目>/index.md` 中写明来源和加载条件。

## 验收标准

- 新增内容有明确目录归属和 `index.md` 入链。
- 使用前可通过 `status/load/source/confidence/load_when` 判断是否适用。
- 没有旧路径、旧术语或外置规则源残留。
- lint / audit / self-check 通过。
