# 执行层依赖文件清单

> 目的：把会触发 skill / cron / 脚本运行时对齐的 KB 文件收缩成少数稳定入口，避免整库任意文档波动都变成执行层噪音。

## 核心原则

- 执行层只依赖“入口文件”和“少数核心规则文件”，不依赖整库散文档。
- 普通知识、素材、参考、历史复盘默认**不**触发执行层对齐。
- 只有本清单中的文件变化，才默认触发 [[规章制度/知识库管理/KB-执行层只读验收协议]]。

## 全局依赖文件

以下文件是所有依赖 KB 的执行层实现都可以稳定依赖的全局入口：

| 文件 | 作用 |
|------|------|
| [[AGENTS]] | 冷启动最短入口 |
| [[规章制度/知识库管理/任务类型索引]] | 唯一运行时任务路由与 BLOCKING 规则 |
| [[规章制度/知识库管理/KB-执行层只读验收协议]] | 规则变更后的最小只读验收输出格式 |

## 项目级依赖文件

项目型 skill / cron / 脚本默认只依赖：

| 类型 | 默认依赖 |
|------|----------|
| 项目任务入口 | `项目知识/<项目>/index.md` |
| 通用产物规范 | 对应 `产物规范/<域>/index.md` |
| 项目特有核心规则 | 仅少数真正被实现硬依赖的规则文件 |

示例：

- `<your-project>`：`项目知识/<your-project>/index.md` + `产物规范/<domain>/index.md`
- 本机系统操作：公开版不内置主机运维规则，使用者按需在本地补充

## 不应直接依赖的内容

以下内容默认不作为执行层直接依赖源：

- `素材库/`、`用户资料/`、`专业知识/` 中的普通参考文件
- `docs/`、设计稿、历史复盘、迁移草案
- 项目目录下的大量流程拆分页，除非实现确实硬编码依赖其中某一页
- 一次性任务产物、日志、缓存、中间状态

## 变更触发规则

当以下变化发生时，默认触发执行层影响判断：

1. 本清单中的全局依赖文件发生规则语义变化
2. 某项目的 `index.md` 发生入口、`depends_on`、`kb_refresh_policy`、BLOCKING 或加载链变化
3. 某产物规范入口 `index.md` 发生流程、质量门禁或验收动作变化
4. 某个被实现明确声明依赖的核心规则文件发生语义变化

当以下变化发生时，默认不触发执行层对齐：

- 普通参考知识改写
- 案例、素材、用户资料补充
- 历史复盘、设计草稿、归档文件更新

## 对项目入口的要求

每个项目 `index.md` 应尽量满足：

- `depends_on` 只列少数稳定入口，不把大量子文档塞进去
- `kb_refresh_policy: runtime`
- 正文中清楚区分：
  - 运行时必读入口
  - 项目目录内的扩展阅读
  - 真正会影响执行层实现的核心规则

## 对 skill / cron / 脚本的要求

- 用 `requires_provides` 声明依赖的稳定入口或核心规则
- 用 `kb_refresh_policy: runtime` 表示执行前读取最新 KB
- 只有硬编码阈值、检查项、固定 prompt 状态时才维护 `spec_versions`
