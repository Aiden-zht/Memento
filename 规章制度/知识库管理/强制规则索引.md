# 强制规则索引

> 本文件只收不可跳过的红线。细节仍在对应业务规范中，但 Agent 执行前必须先看到这些规则。

## 通用执行红线

| 场景 | BLOCKING 规则 | 依据 |
|------|---------------|------|
| 读取 KB | 读取前必须 `git pull origin master` | [[规章制度/知识库管理/知识库内容治理规范/00-读取规范]] |
| 修改 KB | 实质修改必须更新 `version` + `changelog` | [[规章制度/知识库管理/知识库内容治理规范/05-文件规范]] |
|| 修改 KB | 声明完成前必须 lint，通过后 `git add -A` → `commit` → `push` | [[规章制度/知识库管理/知识库内容治理规范/07-Agent行为约束]] |
|| **项目任务知识/规范改动后不 push** | **对 KB 项目任务知识（`项目知识/`）或规范文件的修改，声明完成前必须执行 `git add -A → commit → push`。遗漏推送 → 违规** | [[规章制度/知识库管理/知识库内容治理规范/07-Agent行为约束]] |
| 新增 KB 文件 | `.md` 必须有 frontmatter、`synopsis`、`version`、`changelog` | [[规章制度/知识库管理/知识库内容治理规范/05-文件规范]] |
| 搜索 KB | `draft` / `scaffold` 默认跳过，除非任务明确要求开发草稿规范 | [[规章制度/知识库管理/任务类型索引]] |

## 业务红线

> **业务 BLOCKING 规则由各项目 `项目知识/` 项目任务知识定义**，不在本索引中集中罗列。业务任务的强制规则见对应项目 `项目知识/rules/` 目录，Agent 通过 [[规章制度/知识库管理/知识库内容治理规范/12-项目任务知识接入设计]] 定义的发现机制加载。

## Cron / skill 红线

| 场景 | BLOCKING 规则 | 依据 |
|------|---------------|------|
| 新建 cron | `deliver` 必须确认；面向当前会话默认 `origin`，不能误用 `local` | [[规章制度/Cron流水线运维规范/index]] |
| 依赖 KB 的 cron | prompt 开头必须有 Step 0：`git pull` + 加载 `requires_provides` | [[规章制度/知识库管理/知识库内容治理规范/07-Agent行为约束]] |
| 生产 skill | 依赖 KB 的 skill 必须声明 `requires_provides` 和 `kb_refresh_policy: runtime` | [[规章制度/知识库管理/知识库内容治理规范/07-Agent行为约束]] |
| 本地脚本 | 硬编码 KB 规则的脚本改动后必须做最小验证 | [[规章制度/知识库管理/知识库内容治理规范/07-Agent行为约束]] |

## 使用规则

- 任务索引中的 `BLOCKING 规则` 优先于正文细节。
- 如果正文细节和本索引冲突，先按更严格规则执行，再修正 KB。
- 只把“跳过会导致真实事故”的规则放这里；WARNING、风格建议、背景解释不放这里。
