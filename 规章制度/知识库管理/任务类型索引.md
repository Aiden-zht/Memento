# 任务类型索引 — Agent 执行入口

> 目的：Agent 接到任务后，不靠猜路径，不靠 provides 碰运气，而是直接按任务类型读取必读文件、执行强制规则和最低验证。

## 使用方式

```text
1. 匹配任务类型
2. 读取“必读文件”列出的文件
3. 执行“BLOCKING 规则”列出的不可跳过事项
4. 如信息不足，再用“搜索词”全文搜索兜底
5. 完成“最低验证”后再声明任务完成
```

规则：

- `必读文件` 是主入口；全文搜索只是兜底。
- `BLOCKING 规则` 不得跳过；冲突时以 BLOCKING 优先。
- `draft` / `scaffold` 文件默认跳过，除非任务明确是开发该草稿规范。
- `provides` 只服务 cron/skill 固定依赖，不作为日常知识组织系统。

## Agent 场景差异

| 场景 | 加载策略 | 运行时对齐 |
|------|---------|------------|
| 对话 Agent | 任务索引 → 必读文件 → 必要时全文搜索兜底 | 不维护长期版本表；每次 git pull 后读最新 KB |
| Cron Agent | prompt Step 0 固定加载 `requires_provides`；标签失效时全文搜索兜底 | 执行前读最新 KB；必要时记录 `spec_versions` |
| 子 Agent | 委托方通过 context 传入必要 KB 摘要和 BLOCKING 规则 | 不直接维护版本表 |
| 自建 skill | frontmatter 声明 `requires_provides` 和 `kb_refresh_policy: runtime` | 执行时动态加载 KB；只在硬编码实现中维护 `spec_versions` |

## 如何添加新任务类型

1. 在对应任务区新增一行。
2. 优先写明确 `必读文件`，不要只写关键词。
3. 写清 `BLOCKING 规则` 和 `最低验证`。
4. 只在 cron/skill 固定依赖需要时补 `provides`。
5. 更新本文件 `version` + `changelog`。
