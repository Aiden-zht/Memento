# 任务类型索引 — Agent 执行入口

> 目的：Agent 接到任务后，不靠猜路径，不靠 provides 碰运气，而是直接按任务类型读取必读文件、执行强制规则和最低验证。

## 使用方式

```text
1. 先匹配任务能力：读库 / 写库 / 消化 inbox / 健康检查 / 存废审计 / 迁移重构 / 执行层对齐
2. 再判定任务模式：普通产出 / KB 使用 / KB 维护
3. 读取“必读文件”列出的文件
4. 执行“BLOCKING 规则”列出的不可跳过事项
5. 如信息不足，再用“搜索词”全文搜索兜底
6. 完成“最低验证”后再声明任务完成
```

任务能力入口：[[规章制度/知识库管理/任务能力索引]]。工具只是实现手段，Agent 自行选择。

规则：

- 本文件是唯一任务路由与 BLOCKING 执行入口；其他索引只能引用本文件，不得成为平行 active 权威源。
- `必读文件` 是主入口；全文搜索只是兜底。
- `BLOCKING 规则` 不得跳过；冲突时以本文件 BLOCKING 优先。
- `draft` / `scaffold` 文件默认跳过，除非任务明确是开发该草稿规范。
- `provides` 只服务 cron/skill 固定依赖，不作为日常知识组织系统。


## 任务模式判定（先于任务类型匹配）

Agent 接到任务后，必须先判定任务模式，再进入下方任务类型表。默认是普通产出模式，不能靠关键词升级为 KB 维护。

| 模式 | 触发条件 | 处理方式 | BLOCKING |
|------|----------|----------|----------|
| 普通产出模式 | 用户要求生成、撰写、设计、创建、整理、输出或保存文章、SOUL、角色、提示词、配置、方案、模板、草稿等用户产物 | 输出到对话，或写入用户明确指定路径 | 不修改 Memento；不移动到 inbox；不执行 `git add / commit / push` |
| KB 使用模式 | 用户要求参考、遵守、依据、检查 Memento / KB 规则，但未要求修改 KB | 只读 Memento，按已有规则辅助完成任务 | 不新增、不移动、不固化 KB 资产；不执行 `git add / commit / push` |
| KB 维护模式 | 用户明确要求写入知识库、纳入 Memento、固化规范、更新 KB、维护 agent_mem、消化 inbox、修改规章制度、整理知识库或提交知识库变更 | 按 KB 维护流程修改 Memento；必要时检查 KB→执行层闭环 | `git add / commit / push` 仍需明确授权或现有维护流程明确规定 |

BLOCKING：

- 不得仅凭“知识库、规范、Agent、治理、Memento、SOUL、角色”等关键词进入 KB 维护模式。
- 不得仅凭“可复用”“其他 Agent 可能有用”自动固化到 KB。
- 读取 KB 不等于修改 KB。
- 若用户指定外部 profile、普通文件路径或项目路径，按指定路径交付，不得自行改写为 Memento 知识库落点。

### git 副作用门禁（本文件为唯一 BLOCKING 裁定源）

`git add / commit / push` 是高副作用动作。本文件是其唯一 BLOCKING 裁定源；`AGENTS.md`、`index.md`、`任务能力索引`、`强制规则索引`、`07-Agent行为约束` 等仅能引用、解释或指向本文件，不得载入与本文件冲突的另一套口径。

| 模式 | git 副作用 | 是否允许 |
|------|------------|----------|
| 普通产出模式 | `git add / commit / push` | 禁止 |
| KB 使用模式（只读参考） | `git add / commit / push` | 禁止 |
| KB 维护模式 | 必要时才能 `git add / commit / push` | 仅在用户明确授权，或当前 KB 维护流程明文规定必须推送时 |

- 普通产出模式下，即使用户说"保存"“写入"“落地"，只要目标路径不是 Memento 仓库，就不得执行 git 副作用。
- KB 维护模式中，`完成修改` 不等于 `必须推送`。是否需要 `git add / commit / push` 仍由本表格判定。

## 任务类型 → 执行入口

### 业务任务

> **业务任务由 Memento 内的 `项目知识/<项目>/index.md` 定义。** 项目任务知识的具体流程、必读文件、BLOCKING 规则在本仓库 `项目知识/` 中维护；项目代码仓库只存实现、运行状态和产物，不作为默认规则权威源。
>
> Agent 执行业务任务时：
> 1. 在 Memento 仓库检查 `项目知识/<项目>/index.md`
> 2. 读取 `depends_on` 字段 -> git pull 加载 Memento 对应规范
> 3. 读取 `产物规范/`、`项目知识/<项目>/`、`专业知识/`、`素材库/` 或 `用户资料/` -> 按项目任务知识规则执行
> 4. 如 `项目知识/<项目>/` 不存在，按 [[规章制度/知识库管理/知识库内容治理规范/12-项目任务知识接入设计]] 引导用户在 Memento 内创建项目任务知识

## Agent 场景差异

| 场景 | 加载策略 | 运行时对齐 |
|------|---------|------------|
| 对话 Agent | 任务索引 → 必读文件 → 必要时全文搜索兜底 | 不维护长期版本表；每次 git pull 后读最新 KB |
| Cron Agent | prompt Step 0 固定加载 `requires_provides`；标签失效时全文搜索兜底 | 执行前读最新 KB；必要时记录 `spec_versions` |
| 子 Agent | 委托方通过 context 传入必要 KB 摘要和 BLOCKING 规则 | 不直接维护版本表 |
| 自建 skill | frontmatter 声明 `requires_provides` 和 `kb_refresh_policy: runtime` | 执行时动态加载 KB；只在硬编码实现中维护 `spec_versions` |

## 如何添加新任务类型

1. 在对应任务区新增一行。
2. 优先写明确 `必读文件`，不要只写关键词。
3. 写清 `BLOCKING 规则` 和 `最低验证`。
4. 只在 cron/skill 固定依赖需要时补 `provides`。
5. 更新本文件 `version` + `changelog`。
