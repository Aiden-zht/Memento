# 异常处理与紧急停止

## 1. 常见异常分类

| 异常 | 判断 | 处理原则 |
|------|------|----------|
| 超时 | 总超时、步骤超时、单请求超时 | 标记 timeout；检查最近有效产物；不要无限重试 |
| 外部依赖不可用 | API/网页/数据库/模型/文件共享不可达 | 逐源降级；关键依赖失败则阻断 |
| 认证或权限失败 | 密钥无效、权限不足、白名单/配额问题 | 立即停止相关副作用并通知人工处理 |
| 数据格式异常 | 返回结构变化、解析失败、字段缺失 | 标记 parse_error；保留样本路径或摘要 |
| 验证失败 | BLOCKING 检查不通过 | 阻断下游发布/投递/写入 |
| 副作用不确定 | 不确定是否已发布、发送、删除或写入 | 不重复执行危险动作；先查真实状态 |

## 2. 通用处理流程

```text
发现异常
→ 分类：瞬时/确定性/副作用不确定
→ 写入状态文件和日志
→ 判断是否可降级
→ 判断是否阻断下游副作用
→ 输出人类可读摘要
```

要求：

1. 不得把失败伪装成成功。
2. 不得在未确认幂等性的情况下自动重试有副作用动作。
3. 验证失败、认证失败、权限失败默认阻断下游动作。
4. 降级输出必须显式说明数据新鲜度、缺失部分和风险。

## 3. 紧急停止原则

当出现以下情况，应暂停对应定时任务或停止下游副作用：

| 场景 | 操作 |
|------|------|
| 连续失败达到项目阈值 | 暂停并排查 |
| 产物质量或验证 BLOCKING 失败 | 停止发布/投递 |
| 认证、权限、配额异常 | 停止相关外部调用 |
| 脚本 bug 可能破坏数据或重复副作用 | 立即暂停 |
| 用户明确要求停止 | 立即暂停 |

具体暂停、禁用、恢复命令由当前 Agent 运行时或调度平台决定；通用规范不硬编码平台命令。

## 4. 恢复流程

1. 确认根因已修复：代码、配置、权限、依赖或数据源。
2. 手动运行最小验证，确认脚本/任务可完成。
3. 检查状态文件、关键产物和下游副作用真实状态。
4. 如涉及知识库规则或项目长期流程变化，同步更新 KB 或项目知识。
5. 恢复自动调度，并观察下一次运行结果。

## 5. 记录边界

异常处理需要留下可追溯记录，但记录位置取决于性质：

| 内容 | 位置 |
|------|------|
| 单次运行日志、状态、外部返回 ID | 运行时日志/项目 output，不进 KB |
| 稳定根因和可复用修复模式 | skill 或项目知识 |
| 通用运维规则变化 | 本规范 |
| 基础设施级配置变更 | 当前环境的操作备案或变更记录 |
