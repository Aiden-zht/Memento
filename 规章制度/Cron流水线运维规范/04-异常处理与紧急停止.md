# 异常处理与紧急停止

## 1. 常见异常处理

### 1.1 脚本执行超时

**检测**：LLM 输出中出现 "Script timed out after 120s" 或 "Stream stalled"

**处理**：
1. 报告超时原因和发生阶段（哪个 Phase 超时）
2. 检查上一日 state 文件是否存在且有效
3. 如果有上一日数据 → 用上一日数据做对比报告
4. 如果没有 → 输出 "Pipeline 不可用" 通知
5. **不自动重试**，等待下一次 cron tick

**预防**：
- 增加 script 内部的单请求超时（如 外部 API 从 30s 调到 15s）
- 对于代理请求，增加随机延迟（`time.sleep(random.uniform(0.5, 2.0))`）避免被限流
- 考虑将 script 拆分到独立 no_agent cron job

### 1.2 代理不可用

**检测**：可达性探测失败（curl 探测超时或 403）

**处理**：
1. 报告代理状态
2. 尝试直连（不代理）
3. 直连也失败 → 报告 "外部数据源不可达"，不产出文章
4. **静默跳过**（exit 0 不报错，避免触发错误通知）

### 1.3 平台 API 失败

**检测**：API 返回非 200 状态码或错误码

**处理**（按错误码）：

| 错误码 | 含义 | 处理 |
|--------|------|------|
| 40164 | IP 不在白名单 | 立即通知用户 |
| 40125 | AppSecret 无效 | 检查 .env，立即通知用户 |
| 40007 | media_id 无效 | 重试上传缩略图（永久素材接口） |
| 48001 | freepublish 未灰度 | 降级为草稿创建，标记 draft_saved=True |
| 45009 | 频率限制 | 等待 1 小时后重试，仍失败则通知用户 |
| 45106 | 接口已下线 | 检查代码是否用了旧版接口 |

### 1.4 翻译 API 同时不可用

**处理**：
1. 尝试 AI 翻译（day77/deepseek-chat）
2. 失败 → 尝试备用翻译（xfyun/xopqwen36v35b）
3. 失败 → 使用 FALLBACK_TRANSLATIONS 硬编码表
4. 失败 → 使用 外部 API 原名
5. 每轮降级都记录到 `error_detail` 中

## 2. 紧急停止

### 2.1 停止方法

```bash
# 暂停某个 cron job
<cron系统> pause <任务名称>

# 禁用某个 cron job
<cron系统> disable <任务名称>

# 列出所有 cron job
<cron系统> list
```

### 2.2 何时需要紧急停止

| 场景 | 紧急程度 | 操作 |
|------|----------|------|
| 连续 3 次 Pipeline 失败 | 高 | pause + 通知用户排查 |
| 产出内容被平台驳回（多次） | 高 | pause + 人工审查内容 |
| 代理/网络故障导致全部 API 不可用 | 中 | 不 pause，等自然恢复 |
| 脚本有已知 bug 可能破坏产出 | 高 | pause + 修复 + 手动恢复 |
| 用户要求停止 | 立即 | 立即 pause |

### 2.3 恢复流程

1. 修复问题（代码、配置、网络）
2. 手动验证脚本可用：`cd <workdir> && python3 main.py`
3. 手动执行一次 cron 并确认输出正确
4. 恢复自动运行

## 3. 操作备案

每次 cron 异常处理必须在 `{{WORKSPACE}}/操作备案.md` 中记录：

```markdown
### 2026-06-11 10:15 -- 示例业务日报 Pipeline 超时
- **问题**: cron job 120s 超时，cron_digest.py 外部 API 请求慢
- **处理**: 用 06/10 数据做了对比报告，未生成新草稿
- **影响**: 06/11 日报未发布，06/10 草稿待发布
- **后续**: 需要优化超时配置或拆分 pipeline
- **状态**: 已通知用户
```
