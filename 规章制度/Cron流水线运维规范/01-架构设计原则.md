# Cron 流水线架构设计原则

> 适用范围：任何具备定时调度能力的 Agent 运行时或自动化系统。本文只规定通用架构原则；具体命令、平台字段、业务流程写在对应 skill、项目知识或产物规范中。

## 1. 模式选型

### 1.1 script-only（脚本直跑）

```text
schedule tick → 执行脚本 → stdout/退出码/产物作为结果
```

适用：纯数据收集、固定格式监控、阈值告警、无需语义判断的任务。

原则：
1. 脚本必须幂等，可重复运行不破坏状态。
2. stdout 简洁，只输出人需要看到的摘要；详细日志写 stderr 或日志文件。
3. 脚本内部负责错误处理、超时、重试和退出码。

### 1.2 agent-driven（Agent 运行任务说明）

```text
schedule tick → 加载自包含任务说明 → 可选读取脚本输出 → Agent 判断/总结/执行
```

适用：需要语义判断、摘要生成、多步骤决策、异常解释、人工可读报告的任务。

原则：
1. 任务说明必须自包含，不依赖历史对话。
2. 明确输入、输出、边界、副作用和验证方式。
3. 每次运行都是独立 session，不能假设“上次已加载过规范”。
4. 依赖 KB 的任务必须在开头声明运行时加载最新规范的步骤或等价机制。

### 1.3 混合模式

```text
脚本收集数据 → Agent 分析/决策 → 脚本执行确定性操作
```

推荐用于复杂流水线：数据收集和确定性操作交给脚本，语义判断和报告交给 Agent。

## 2. 包装脚本规范

包装脚本最少应包含：

```bash
#!/usr/bin/env bash
set -euo pipefail

run_id="$(date '+%Y%m%d_%H%M%S')"
workdir="/path/to/workdir"
cd "$workdir" || { echo "ERROR workdir_not_found $workdir"; exit 1; }

echo "=== Pipeline Start: $run_id ==="

# 1. 检查配置/凭据/依赖
# 2. 检查上游产物（如有）
# 3. 执行主逻辑，主逻辑内部管理单请求 timeout/retry
python3 main.py

echo "State file: output/state_${run_id}.json"
echo "=== Pipeline Success: $run_id ==="
```

## 3. 前置检查清单

1. 工作目录存在。
2. 必要配置、凭据、环境变量存在；不要把密钥写进知识库。
3. 外部依赖可达；如果需要代理，由项目实现声明，不在通用规范硬编码协议或端口。
4. 上游产物存在且格式可解析。
5. 运行数据写入工作区的 `output/`、`logs/` 或平台状态存储，不写入知识库内容目录。

## 4. 依赖管理

如果定时任务依赖技能、规范或项目知识：

1. 在任务说明或实现中声明依赖来源。
2. 执行前读取最新 KB；标签定位失败时用全文搜索兜底。
3. 不把规范正文复制进长期 prompt；只保留加载入口和必须遵守的 BLOCKING 摘要。
4. 平台字段（如 schedule、deliver、skills、workdir、timeout）属于具体运行时配置，不写进通用法规正文。

## 5. 文件产出约定

推荐结构：

```text
output/state_<run_id>.json   # 机器可读状态
output/result_<run_id>.*     # 业务结果
logs/<run_id>.log            # 详细日志（如需要）
```

运行数据、缓存、日志、草稿 ID、外部平台返回 ID 不进入知识库；只有长期规则、接口契约、项目事实和可复用经验才进入 KB。
