# 超时与重试策略

## 1. 超时分层

```text
调度系统总超时
└─ 流水线/步骤超时
   └─ 单请求/单命令超时
```

每层都必须独立设置或明确采用平台默认值。

| 层级 | 约束 | 原则 |
|------|------|------|
| 调度系统总超时 | 整次 tick 的硬上限 | 必须大于最慢合法运行时间；超时后要有可见状态 |
| 流水线/步骤超时 | 某阶段最多运行多久 | 长任务拆阶段，避免一个阶段吞掉全部预算 |
| 单请求/单命令超时 | 外部 API、网页、命令调用 | 快速失败，记录原因，进入降级或失败路径 |

## 2. 重试原则

1. 只对瞬时故障重试：网络抖动、限流、临时 5xx。
2. 不对确定性错误盲目重试：配置缺失、认证失败、格式错误、权限不足。
3. 重试必须有上限和退避；不能无限循环拖垮整次任务。
4. 每次重试都记录到状态或日志，最终报告只保留必要摘要。

## 3. 外部依赖配置

外部依赖包括 HTTP API、网页、数据库、消息平台、模型服务、代理、文件共享等。通用要求：

1. 每个依赖有独立 timeout。
2. 每个依赖有错误分类：timeout、auth_error、rate_limited、bad_response、unavailable、parse_error。
3. 代理、区域、DNS、证书等环境差异属于项目实现或部署说明，不在通用规范硬编码。
4. 多数据源任务应逐源降级，不因单个非关键数据源失败而直接终止。

## 4. 失败降级

```text
当日运行失败
→ 检查是否有最近一次有效产出
→ 有：输出降级报告，标明使用旧数据/部分数据
→ 无：输出不可用报告，说明阻断原因
```

原则：

1. 失败不能静默吞掉；用户或下游系统必须看到状态。
2. 降级产物必须显式标记，不能伪装成新鲜完整产物。
3. 对有副作用的任务，失败后不要自动重复执行危险操作；先确认幂等性。
4. 连续失败达到项目定义阈值时，应暂停或通知人工处理；阈值写在项目知识或运行时配置中。

## 5. Agent 验证降级

如果流水线包含独立验证 Agent：

1. 验证超时或不可用时，不得默认视为通过。
2. 是否允许跳过验证由对应产物规范或项目知识决定。
3. 跳过验证必须写入状态：`validation.status = skipped`，并说明原因。
4. 对 BLOCKING 级验证，不能用“超时跳过”绕过发布或执行。
