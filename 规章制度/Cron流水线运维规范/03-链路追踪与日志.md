# 链路追踪与日志

## 1. 状态文件格式

每个 Pipeline 执行后必须产出 `state_YYYYMMDD.json`，格式：

```json
{
  "run_id": "20260611_100000",
  "status": "success | partial | failed",
  "generated_at": "2026-06-11T10:04:18.336153",
  "pipeline_version": "3.0.0",
  "error": null,
  "error_detail": null,
  "output_artifacts": {
    "state_file": "output/state_20260611.json",
    "html_file": "output/digest_20260611_rich.html",
    "kpi_file": "output/kpi_records.json"
  },
  "validation": {
    "passed": true,
    "blocking_count": 0,
    "warning_count": 0,
    "validated_by": "agent_b_delegated",
    "validated_at": "2026-06-11T10:06:00"
  },
  "publish": {
    "status": "draft_created",
    "media_id": "xxx",
    "published_at": "2026-06-11T10:07:00"
  },
  "agents": {
    "a_score": 95,
    "b_score": 100
  }
}
```

**关键字段**：
- `status`：`success`（全部成功）、`partial`（部分失败，有降级）、`failed`（完全失败）
- `error`：错误类型代码（如 `timeout`、`api_error`、`validation_failed`）
- `error_detail`：人类可读的错误描述
- `validation.validated_by`：记录验证方式（`agent_b_delegated`、`skipped_timeout`、`skipped_disabled`）

## 2. Wrapper 输出约定

Wrapper 脚本的 stdout 必须包含结构化标记，方便 LLM 解析：

```bash
echo "=== Pipeline Start ==="
echo "[$TIMESTAMP] Phase 1: Scraping..."
echo "[$TIMESTAMP] Found 12 deals"
echo "[$TIMESTAMP] Phase 2: Uploading images..."
echo "[$TIMESTAMP] Uploaded 9/12 images"
echo "[$TIMESTAMP] Phase 3: Generating HTML..."
echo "📄 State file: /path/to/output/state_20260611.json"
echo "📄 HTML file: /path/to/output/digest_20260611_rich.html"
echo "=== Pipeline Success ==="
```

**标记格式**：
- `===` 包裹的开始/结束标记（LLM 用这个判断 pipeline 完整性）
- `📄` 标记文件路径（LLM 用这个找到产出文件）
- `⚠️` 标记 WARNING 级别信息
- `❌` 标记 ERROR 级别信息

**禁止**在 stdout 中输出冗长的调试日志。详细日志走 stderr 或文件。

## 3. Cron 链路完整性

### 3.1 链路检查清单

每次 cron run 结束后，自动检查：

1. **状态文件是否存在** — `output/state_YYYYMMDD.json` 存在且非空
2. **状态文件格式正确** — JSON 可解析，包含 `status` 字段
3. **产出文件存在** — HTML 文件、KPI 文件存在
4. **LLM 输出中引用了正确的产出文件** — LLM 读取了脚本输出的文件路径
5. **KPI 已评分** — `kpi_records.json` 包含本次记录

### 3.2 链路断裂检测

如果出现以下情况，标记为**链路断裂**：

| 断裂类型 | 检测方式 | 处理 |
|----------|----------|------|
| 脚本执行超时 | LLM 输出中无 `=== Pipeline Success ===` | 报告超时，用上一日数据对比 |
| 状态文件不存在 | 脚本输出中没有 `📄 State file:` 或文件不存在 | 报告失败原因 |
| LLM 未读取产出文件 | LLM 输出中未引用产出文件路径 | 报告链路断裂 |
| KPI 未评分 | `kpi_records.json` 无本次记录 | 报告评分遗漏 |

### 3.3 日志存储

- 每次 cron run 的结果由 Agent 本地保存到工作区日志目录
- 不应在 cron script 中额外写入日志文件（除非有特殊需求）
- 如果需要持久化状态，写入 `output/` 目录，不写入 `专业知识/`、`素材库/` 或 `用户资料/` 目录

## 4. 运行后验证

Pipeline 完成后应自动验证：

```bash
# 验证 state JSON 完整性
python3 -c "
import json, sys
with open('output/state_20260611.json') as f:
    d = json.load(f)
assert d['status'] in ('success', 'partial', 'failed')
assert 'games' in d or 'articles' in d
assert 'output_artifacts' in d
print(f'Status: {d[\"status\"]}, Games: {len(d.get(\"games\", []))}')
"
```

**注意**：此验证应在 script 内部完成（Agent A 自检），不需要 LLM 来做。LLM 只需读取状态文件确认 pipeline 整体状态。
