# 链路追踪与日志

## 1. 状态文件最低结构

每次 Pipeline 执行后应产出机器可读状态，推荐 JSON：

```json
{
  "run_id": "20260616_100000",
  "status": "success | partial | failed | skipped",
  "started_at": "2026-06-16T10:00:00Z",
  "finished_at": "2026-06-16T10:03:00Z",
  "pipeline_version": "1.0.0",
  "error": null,
  "error_detail": null,
  "inputs": {},
  "output_artifacts": {
    "state_file": "output/state_20260616_100000.json",
    "result_file": "output/result_20260616_100000.md"
  },
  "validation": {
    "status": "passed | failed | skipped | not_required",
    "blocking_count": 0,
    "warning_count": 0,
    "checked_by": "script | agent | external",
    "checked_at": "2026-06-16T10:02:00Z"
  },
  "delivery": {
    "status": "sent | saved | skipped | failed",
    "target": "configured-target-or-null",
    "delivered_at": null
  }
}
```

关键字段：

| 字段 | 要求 |
|------|------|
| `run_id` | 唯一标识一次运行 |
| `status` | 只能使用固定枚举，不能写自由文本 |
| `error` / `error_detail` | 失败或降级时必须填写 |
| `output_artifacts` | 记录产物路径或外部对象引用 |
| `validation` | 记录验证是否执行、结果和原因 |
| `delivery` | 记录是否已发送、保存或跳过 |

## 2. stdout 输出约定

stdout 面向调度器和 Agent，应短、结构化、可解析：

```bash
echo "=== Pipeline Start: $run_id ==="
echo "[$timestamp] Phase collect: ok"
echo "[$timestamp] Phase validate: warning_count=1"
echo "State file: output/state_${run_id}.json"
echo "Result file: output/result_${run_id}.md"
echo "=== Pipeline Success: $run_id ==="
```

约定：

1. 用固定 start/end 标记判断流水线是否完整。
2. 明确输出 state/result 路径。
3. WARNING/ERROR 使用稳定前缀。
4. 冗长 debug 信息写 stderr 或日志文件，不刷 stdout。

## 3. 链路完整性检查

每次运行结束后，至少检查：

1. 状态文件存在且非空。
2. 状态文件 JSON 可解析，`status` 合法。
3. `output_artifacts` 中声明的关键产物存在，或外部引用可验证。
4. 如果有验证步骤，`validation.status` 不是空值。
5. 如果有下游投递/发布，`delivery.status` 不是空值。

断裂类型：

| 类型 | 判断 | 处理 |
|------|------|------|
| 脚本未完整结束 | 无 success/end 标记或退出码非零 | 标记 failed，保留日志 |
| 状态缺失 | state 文件缺失/不可解析 | 标记链路断裂 |
| 产物缺失 | state 声称产出但文件不存在 | 阻断下游副作用 |
| 验证缺失 | 应验证但无验证结果 | 按产物规范判断是否 BLOCKING |
| 投递不明 | 下游动作无状态 | 不声称已完成 |

## 4. 日志存储

1. 日志属于运行数据，不写入知识库内容目录。
2. 需要长期追踪的状态放在项目工作区、Agent 运行时状态目录或外部可观测系统。
3. 知识库只记录可复用的规则、接口契约和项目长期事实，不记录单次运行日志。
